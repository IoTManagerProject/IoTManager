# Руководство: работа с веб-панелью magicIoTm

> How-to документ. API панели — [reference/magiciotm-api.md](../reference/magiciotm-api.md),
> менеджер устройств и статусы — [reference/device-status-fsm.md](../reference/device-status-fsm.md).

Панель — одностраничное приложение (SPA) с боковой панелью и основной областью.

## Сайдбар: «Проекты» и «Устройства»

- **📁 Проекты** — дерево категорий и проектов. Кнопки «+ Категория» и «+ Проект».
  Управление: создание, переименование, копирование, перенос, удаление
  (с автоматическим резервным копированием в `projects/.backups`).
  При переименовании категории/проекта, переносе и копировании автоматически
  обновляется путь `[platformio] data_dir` в `platformio.ini` проекта
  (`tools/magicIoTm/projects/<категория>/<проект>/data_svelte`).
  Защищённый проект **PlatformIO** работает напрямую с корневым `myProfile.json` —
  его нельзя переименовать, перенести или удалить.
  Текущий проект автоматически открывается при запуске.
- **💡 Устройства** — кнопка «🔍» сканирует сеть: список доступных сетевых интерфейсов
  (реальные IP; исключаются loopback `127.x.x.x` и link-local `169.254.x.x`; для Wi-Fi
  показывается SSID), «Сканировать все подсети» (`__all__`), до 64 пингов параллельно,
  прогресс по SSE. Устройство можно добавить вручную по IP-адресу.
  Кнопка «⧉» копирует устройство в проект — существующий (выбор категории
  и проекта) или новый (создаётся из корневого шаблона). Источник — сохранённые
  файлы RAM или FS устройства; правила те же, что у кнопок «⤵ Из устройства»
  в панели проекта: settings.json → настройки (`iotmSettings`, кроме id/ip/root),
  profile.json/flashProfile.json → платформа из default_envs (несовместимые
  модули отключаются) и активность модулей. Если раздел FS локально пуст
  и устройство в сети, панель сначала предложит скачать раздел FS на диск
  (с прогрессом), после чего продолжит копирование.

## Панель проекта

- **Платформа** — выбор целевой платформы из `[env:*]` `platformio.ini`; при смене
  платформы несовместимые модули отключаются автоматически.
- **Настройки устройства** — редактирование `iotmSettings`: имя, группа WG, точка
  доступа AP, параметры роутера, MQTT-сервер, NTP, I²C, таймзона, web-логин/пароль, репитер.
  Значения можно скопировать из другого проекта.
- **💠 Модули** — список модулей по секциям с чекбоксами; групповое управление,
  копирование настроек/модулей из других проектов и с устройств.
  Совместимость с платформой подсвечивается. Статус размера модуля: красная
  строка — ошибка компиляции (для этой платформы или для всех), жёлтая — размер
  не замерялся; точная причина — во всплывающей подсказке.
- **Индикатор памяти** — расчёт заполненности FLASH/RAM/FS из `modinfo.json` и `platforms.json`.
  Ёмкость FS (`total_fs`) берётся из `platforms.json`, а если её там ещё нет —
  из размера собранного образа ФС: `littlefs.bin`/`spiffs.bin` в `.pio/build/<платформа>/`
  для ESP либо `lt_littlefs.bin` в корне проекта для LibreTiny (`bk7231n`, образ
  собирает кастомный таргет `tools/lt_fsbuild.py`).
- **⚖️ Замер размера** — прирост размера прошивки по модулям: «Все модули»,
  «Отдельный модуль», «Базовая прошивка», «Профиль», «Без размера».
  «Замер базы» перед запуском спрашивает область: текущая платформа или все
  платформы; результат дописывается в историю замеров `platforms.json`
  (версия прошивки из `Const.h` + дата), в итоге показывается, на сколько
  изменился базовый размер.
- **🔨 Сборка** — этапы: подготовка профиля (PrepareProject) → сборка FS (buildfs) →
  сборка прошивки (build); поэтапный SSE-лог; расчёты Flash/RAM/FS.
- **🚀 Загрузка (Upload)** — запись прошивки/ФС на устройство.
- **🗂️ Файловая система FS** — просмотр и редактирование файлов `data_svelte`
  проекта (расположен ниже «📝 Описание проекта»). Дерево файлов + текстовый
  редактор, «💾 Сохранить» пишет файл локально в проект. Кнопки «⤵ Получить файлы»
  и «⤵ Получить этот файл» берут файлы из устройства (RAM/FS — сохранённые копии
  или напрямую с устройства; выбор источника — в модальном окне; источник
  «с устройства» предварительно проверяется пингом — при неудаче выводится
  сообщение «Устройство … не в сети (ping не отвечает)»). Бинарные файлы
  (`*.gz`, `favicon.ico`)
  видны в дереве, но их содержимое в редакторе не открывается (только имя
  и размер); получать их с устройства кнопками «⤵ …» можно, «💾 Сохранить»
  для них недоступна. Правки в редакторе отслеживаются: у имени файла с
  несохранёнными изменениями появляется индикатор «●», а при уходе панель
  спросит, сохранить ли изменения (см. «Защита несохранённых правок»).

### Валидация

- Имя устройства: ≤ 64 символов, без пробелов, уникально в пределах всех проектов (включая корневой PlatformIO).
- AP SSID: уникален (может быть пустым).

## Менеджер устройств

При клике на устройство открывается менеджер: верхняя строка кнопок, ниже — разделы **RAM** и **FS**.

Если устройство «не в сети» (серый/красный статус), кнопки «⤵ Получить файлы» и
«⤵ Получить этот файл» сначала проверяют его пингом: ответил — получение
продолжается (статус локально меняется на «в сети»), нет — предупреждение
«Устройство … не в сети (ping не отвечает)» без запуска скачивания.

### Защита несохранённых правок

Правки во всех редакторах (RAM и FS устройства, FS проекта) отслеживаются: у имени
файла в заголовке редактора появляется индикатор «●». Модалка «Сохранить /
Не сохранять / Отмена» показывается при:

- переходе к другому файлу в дереве;
- смене устройства или выходе из устройства (клик по другому устройству, «←»);
- открытии другого проекта;
- «⤵ Получить этот файл» — полученный файл затирает содержимое редактора.

Переход выполняется после «Сохранить» только при успешном локальном сохранении
(иначе остаёмся в редакторе); «Не сохранять» уходит без записи правок. Авто­
восстановление последнего выбранного файла (возврат на устройство/проект,
«🔄 Обновить деревья») редактор с правками не затирает. Закрытие или обновление
страницы с несохранёнными правками подтверждается нативным окном браузера.
Потеря фокуса редактора (клик по кнопке или соседнему редактору) модалку не
вызывает — несохранённость видна по индикатору «●».

### Раздел RAM

Кнопка «⤵ Получить файлы» скачивает конфигурационные файлы по WebSocket (порт 81):

| Файл в папке RAM | Источник |
|---|---|
| `items.json`, `widgets.json`, `config.json`, `scenario.txt`, `settings.json` | `/config\|` |
| `ota.json`, `profile.json` | `/profile\|` |

- «💾 Сохранить» — всегда сохраняет изменения в локальную копию (RAM), а для
  файлов, поддерживаемых прошивкой, дополнительно записывает их на устройство
  обратными WS-командами `/gifnoc|` (config.json), `/oiranecs|` (scenario.txt),
  `/sgnittes|` (settings.json), `layout.json` (`/tuoyal|`), `devlist.json`
  (`/tsil|`) — если устройство «в сети» (зелёный статус). Лимит — 50 КБ на один
  фрейм. Итог показывается в сообщении: «Сохранено локально и в устройство»,
  «Сохранено локально, устройство не доступно», «Сохранено локально, ошибка
  записи в устройство: …»; для остальных файлов (items.json, profile.json,
  ota.json, …) — просто «Сохранено локально», запись их на устройство прошивка
  не поддерживает.
- Показывается прогресс скачивания (модальное окно).

### Раздел FS

Кнопка «⤵ Получить файлы» рекурсивно скачивает файловую систему по HTTP (порт 80):
`/list?dir=<path>` и `/<path>?download=1`. Редактор сохраняет изменения **локально**
(обратной записи на устройство для FS нет, «💾 Сохранить» показывает
«Сохранено локально»). Бинарные файлы (`*.gz`, `favicon.ico`)
видны в дереве, но их содержимое в редакторе не открывается (только имя и размер).

Кнопка «⤵ Получить этот файл» (в панели FS устройства) скачивает с
устройства только выбранный в дереве файл — по HTTP `/<path>?download=1` —
и сохраняет его в папку устройства (FS); работает и для бинарных файлов,
содержимое которых в редакторе не открывается.

### Прочие действия

- **✕** — удалить папку/записи устройства (при занятости — в фоновом потоке).
- **🔁** — перезагрузка устройства по WS (`/reboot|`).
- «Добавить устройство» — регистрация устройства по IP вручную.
- Копирование `settings.json` (RAM/FS) / `profile.json` (RAM) / `flashProfile.json` (FS)
  с устройства в открытый проект.

## Экспорт/импорт конфигурации

- Экспорт текущей конфигурации в JSON (`myProfile_<ts>.json`).
- Импорт базового конфига корневого `myProfile.json` как шаблона (`/config/import-root`).
- Копирование `iotmSettings` и `modules` из других проектов.

## USB-прошивка

- При старте панель проверяет наличие **PlatformIO**: если `pio` не найден
  (PATH, `~/.platformio/penv`, окружение панели), показывается модальное окно
  с предложением автоматической установки (`POST /api/tools/platformio/install`);
  установленный панелью pio автоматически находится при сборке и прошивке.
- Проверка/автоустановка/обновление **esptool** на старте и по запросу.
- Определение подключённого чипа (модель, семейство, объём flash).
- Режимы записи: только FS / только прошивка / полная (`full`).
- Защита: если flash чипа меньше требуемого для платформы — прошивка отменяется.
- Перед записью FS проверяется каталог данных `data_svelte` из `platformio.ini`.
  Если путь устарел (проект переносили, категорию переименовывали), прошивка
  останавливается до запуска pio, и показывается модалка «Исправить и прошить»:
  она перезаписывает только строку `data_dir` и повторяет прошивку.

## OTA-прошивка

- Режимы: `firmware` / `fs` / `full`.
- Способ записи FS: образ (`flash` — `littlefs.bin`/`spiffs.bin`) или пофайлово (`copy`).
- Локальный HTTP-сервер `.bin`, проверка совпадения платформы устройства и проекта,
  список совместимых онлайн-устройств.
- **LibreTiny (`bk7231n`)**: OTA **прошивки** поддержана (устройство качает
  `firmware.bin` — UF2-образ — и пишет через `Update`, `U_FLASH`); запись образа ФС
  по воздуху невозможна в принципе (`Update.begin()` принимает только `U_FLASH`),
  поэтому режимы «ФС: записать образ» / «Полная (образ ФС + прошивка)» скрыты в UI,
  а API `/api/ota/start` возвращает 400 с подсказкой (copy или USB, таргет `flashfs`).
  Детали и чек-лист тестов на железе: [TODO.md](../../TODO.md).

## Проверка scenario.txt

Кнопка «🔍 Проверка» в редакторе выполняет анализ:

- **Скобки** — баланс `{}`, `()`, `[]` с указанием строк и позиций непарных скобок
  (комментарии `#` и строки игнорируются).
- **if/then/else** — наличие пар if-then, корректность конструкции, then/else без if
  (рекурсивный разбор с учётом вложенности).
- **Зацикливание** — циклические зависимости между переменными (event-driven).
- **Переменные** — `config.json` из той же папки, сравнение ID элементов с переменными сценария.
- **Встроенные функции** — `ID.функция()` ищется строго по модулю элемента (по `subtype`
  в `config.json`) в `about.funcInfo[].name` из `modinfo.json` + зарезервированные имена
  из `src/modules/sceninfo.json`.

Кнопка **«🔍 Проверка»** в редакторе выполняет анализ (всегда заново). Результат
запоминается в кэше текущей сессии отдельно для каждого `scenario.txt` каждого
устройства/проекта: при возврате к файлу панель «Проверка» показывается
автоматически с сохранённым результатом. Сама проверка при открытии файла не
запускается. Закрытие панели кнопкой **✕** очищает кэш этого сценария (этого
устройства/проекта) — панель больше не показывается автоматически, пока вы не
запустите проверку кнопкой снова.

Секция **«🗂️ Файловая система FS»** имеет фиксированную высоту: при выводе
длинных результатов проверки секция не растягивается по вертикали —
тело проверки прокручивается внутри панели.

В разделе **«🗂️ Файловая система FS»** выбранный файл запоминается на текущую
сессию отдельно для каждого устройства и проекта: при переходе на другое
устройство или проект и возврате файл выбирается в дереве автоматически.

Списки функций отдаёт `GET /api/scenario/functions` (`reserved` + `bySubtype`).
